# Исцеляющий сон

Цель — чтобы Нейра могла фиксировать сбои, собирать советы у доверенных нейросетей и учиться точнее формулировать запросы «во сне».

## Контур

- **Детект**: любой модуль может вызвать `HealingSleep::record_incident`, передав краткое описание, область и серьёзность.
- **Журнал**: последние N инцидентов и советов сохраняются в ограниченную очередь (TOML-параметр `journal_limit`).
- **Совет**: если политика (`allow_external_consultant`) разрешает, запрос формируется тренером подсказок и отправляется консультанту (пока заглушка `NoOpConsultant`).
- **Обучение**: тренер хранит успешные пары «проблема → совет», чтобы последующие запросы содержали контекст и сигналы.

## Конфигурация

`spinal_cord/config/healing_sleep.toml`

```toml
[healing_sleep]
enabled = true
allow_external_consultant = false
preferred_consultant = "openai:gpt-4.1"
max_incidents_per_cycle = 5
journal_limit = 120
reflection_window_minutes = 45
min_severity = "medium"
```

Настройки можно переопределить переменной `HEALING_SLEEP_CONFIG`, передав путь к файлу.

## Уровни серьёзности

```
low < medium < high < critical
```

Порог `min_severity` определяет, когда запрашивать внешний совет. Менее серьёзные инциденты просто попадают в журнал.

## Расширение

- Подключить реального консультанта (HTTP-клиент, список доверенных моделей).
- Планировщик «ночных» прогонов: запускать `record_incident` для накопленных ошибок перед режимом сна.
- Метрики: число инцидентов, успешных советов, среднее время восстановления.

## Безопасность

- Все внешние запросы проходят через whitelisted-провайдеров.
- Можно полностью отключить подсказки (`allow_external_consultant = false`) — тогда модуль работает как ретеншн журнала.
- Для критических подсказок стоит предусмотреть HITL-апрув перед применением.
